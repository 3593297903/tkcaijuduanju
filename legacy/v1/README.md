# 原方法归档（2026-10-28）

本目录保存已经实际使用过的方法和脚本，不随新系统改写。manifest.json中的脚本逐字节复制自当日文件。

## 实际采集方法

1. 使用用户自己的Chrome配置与已有登录状态，连接已安装的浏览器工具。
2. 在目标账号打开Short dramas，先启用网络响应记录，再刷新页面。
3. 读取页面自然发出的 `/api/drama/user/drama_list/` 响应，保存每页原始JSON。记录真实采集起止时间。
4. 页面自动滚动触发分页，持续读取至 `hasMore=false`。通过 `dramaID` 字符串去重并核对游标，页面卡片另存显示值。
5. 接口字段包括dramaID、dramaName、numWatched、description、themes、cover、zoomCover、numVideos。接口整数和页面K/M折算值分开保存。
6. 新剧小封面只保存对应页面缩略图；新简介按实际采到的英文内容翻译。未取得的发布时间留空，不由ID推算。

浏览器采集动作原先运行在会话REPL内，未形成独立一键采集程序。本归档保留其步骤和接口结构，不把旧脚本声称为已独立自动运行的采集器。

## 统计和报表

`prepare_reports.py`读取已保存的三个账号checkpoint、上一轮历史、初始基线与中文资料；按账号+剧目ID匹配，生成JSON、CSV及离线HTML。

`full_numbers/build_workbooks.mjs`使用运行环境提供的 `@oai/artifact-tool` 生成三个带小封面、中文资料、初始/昨天/今天对比的XLSX。

`full_numbers/verify_and_package.py`检查保存后的表格数值、公式、图片和历史基线，再打包。

`trend_analysis.py`按每天最后快照比较，使用真实采集间隔折算24小时增量，避免跨日区间冒充单日。

## 旧方法的已知限制

- 日期、输入目录与部分剧目数量写死，复跑别的日期需修改。
- 导出依赖当时的Codex运行环境，不能仅复制脚本就假定所有电脑可运行。
- Chrome断连需要恢复；原流程部分新增资料依靠页面补采。
- 列表响应没有确认的整剧发布时间，关联预览视频日期不等于整剧发布日期。
- 本机完整历史备份有384部资料、21次快照和三个原始checkpoint；公共仓库不包含该备份。

## 固定数据口径

初始值固定为每部剧首次保存值；缺失日不补0；新增剧不按前一天0计算；负向变化照实保留；整剧播放量与单条视频播放量不混用；接口整数与页面折算值不混算。
